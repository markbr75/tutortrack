# E33 — Workflow designer: manual tests

**Scope.** The Workflows area that replaced Automations: one sequence model (a start, an optional **Stop when**, steps with When, Only if and Do, and Yes / No splits one level deep); the 15 built-in workflows that replaced the hard-wired invoicing, chasing, lesson, sales and expiry processes, with their first versions taken from each organisation's settings; the sequence editor; Preview for a record, Coming up and the Runs list with Cancel and Retry; safety rules; the move from Automations; and the `workflow.run_failed` webhook. The engine is still E14's (`AutomationRunWorkflow`, `AutomationScheduleWorkflow`), so the E14 file still covers actions, guardrails and loop detection. Spec: [E33](../epics/E33-workflow-designer.md), ADR 0047.

**Built differently from the spec (Implementation notes win):**
- **Invoicing cycle** is one card (**Start an invoice run**, with the review window, when to issue and whether to email). Approvals and the run's own steps stay in code.
- **Enquiry follow-up** is two built-ins: **Enquiry follow-up** (new enquiries) and **Enquiry stage time limits** (each later stage). That makes 15 built-ins, not 14.
- Lesson reminders and the unconfirmed lesson chaser start "near a date": a 15-minute sweep picks lessons whose moment just came, so a moved lesson is picked at its new time.
- Some settings stay settings: `delivery.report_due_hours`, `delivery.unconfirmed_action`, `growth.review_after_lessons` and `review_after_trial`, and the billing `review_days`, `auto_issue` and `auto_send` (for runs started by hand). The replaced settings stay readable for one release, and changing them is refused ("This is now set in Workflows").
- Actions that send a TutorTrack notification have **Edit wording**, which opens Settings › Notifications. They don't pick a message template.
- **Coming up** counts records before the start's own "only if" questions (the panel says so).
- Runs have no `waiting_for`/`next_wake_at` columns; where a run is comes from its step log.
- The `/automations` and `/automation-runs` API aliases, `POST /automations/{id}/test` and the replaced settings are kept for one more release.

**Common preconditions.** Stack with Celery, the Temporal worker and the Temporal UI (http://localhost:8233); seed loaded. The worker task runs `sync_builtin_workflows` at start, which installs the built-ins for every organisation. Without docker-compose, run `cd backend && uv run python manage.py sync_builtin_workflows` once. Screens: `/workflows` (tabs **Built-in**, **Your workflows**, **Templates**, **Runs**) and `/workflows/<id>` (the editor, with **Preview for a record** and **Coming up**). Owner, Admin and Branch Manager hold `automation.*`; Finance holds `automation.view` and `automation.builtin.manage`; Coordinator holds neither. The dev server can't skip time: to see a wait end, shorten it in the editor (for example "After 1 minute") on a copy, or check the run's wait in **Runs** and in the Temporal UI.
